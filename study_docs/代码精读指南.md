## 0. 阅读准备与代码地图

### 0.1 三条阅读原则

1. **跟着数据流走，不按目录翻**：代码是为"训练循环"服务的，按 `train.py → 环境 → 算法` 的调用顺序读，每一步都知道自己在数据流的哪个位置；
2. **先配置后实现**：config 文件告诉你"有哪些旋钮"，实现告诉你"旋钮接到了哪"。读 `legged_robot.py` 时旁边开着 `legged_robot_config.py`；
3. **随手标注张量形状**：Isaac Gym 风格的代码全靠张量形状对齐，如 `dof_pos: (4096, 12)`。读懂形状 = 读懂一半。

## 1. 入口层：scripts/

### 1.1 `scripts/train.py`（48 行）—— 训练入口

整个文件去掉版权头后只有 17 行有效代码，是理解全局的起点：

```python
def train(args):
    env, env_cfg = task_registry.make_env(name=args.task, args=args)        # ① 建环境
    ppo_runner, train_cfg = task_registry.make_alg_runner(env=env, name=args.task, args=args)  # ② 建算法
    ppo_runner.learn(num_learning_iterations=train_cfg.runner.max_iterations,
                     init_at_random_ep_len=True)                            # ③ 训练

if __name__ == '__main__':
    args = get_args()     # 解析命令行（--task 等），见 helpers.py
    train(args)
```

精读要点：
- **三步范式**：环境、算法、训练，全部委托给 `task_registry` 装配，入口本身没有任何逻辑——这就是注册表模式的价值；
- `init_at_random_ep_len=True`：训练开始时给每个环境一个随机的 episode 进度，让 4096 个环境的重置时刻**错开**（去同步），避免数据分布出现周期性震荡；
- 第 35-36 行的 `import isaacgym` + `from legged_gym.envs import *`：**import 顺序不能换**——Isaac Gym 必须在 torch 之前 import（其底层 C 扩展对 torch 的符号有依赖要求）；`envs` 包的 import 会触发 `envs/__init__.py` 里的任务注册。

### 1.2 `scripts/play.py`（122 行）—— 评估与部署导出

```python
def play(args):
    env_cfg, train_cfg = task_registry.get_cfgs(name=args.task)
    # —— 覆盖配置，做"标称条件"评估 ——
    env_cfg.env.num_envs = min(env_cfg.env.num_envs, 50)   # 最多 50 个环境，方便观察
    env_cfg.terrain.num_rows = 5
    env_cfg.terrain.num_cols = 5
    env_cfg.terrain.curriculum = False                     # 关课程
    env_cfg.noise.add_noise = False                        # 关观测噪声
    env_cfg.domain_rand.randomize_friction = False         # 关摩擦随机化
    env_cfg.domain_rand.push_robots = False                # 关随机推搡

    env, _ = task_registry.make_env(name=args.task, args=args, env_cfg=env_cfg)
    obs = env.get_observations()
    train_cfg.runner.resume = True                          # 强制加载模型
    ppo_runner, train_cfg = task_registry.make_alg_runner(env=env, name=args.task, args=args, train_cfg=train_cfg)
    policy = ppo_runner.get_inference_policy(device=env.device)  # 注意：拿到的是 act_inference

    if EXPORT_POLICY:                                     # 导出 JIT 供 C++ 部署
        path = os.path.join(LEGGED_GYM_ROOT_DIR, 'logs', train_cfg.runner.experiment_name, 'exported', 'policies')
        export_policy_as_jit(ppo_runner.alg.actor_critic, path)
```

主循环（77-114 行）做的事：

```python
for i in range(10 * max_episode_length):     # 跑 10 个 episode 时长
    actions = policy(obs.detach())           # 确定性推理（取均值，不采样）
    obs, _, rews, dones, infos = env.step(actions.detach())
    # 可选：RECORD_FRAMES 录帧、MOVE_CAMERA 移动相机
    # 前 100 步：记录 0 号机器人 1 号关节的目标角/实际角/速度/力矩/指令/接触力
    # 第 100 步：logger.plot_states() 画对比曲线
    # 前 1 个 episode：统计各项 episode 奖励均值并打印
```

精读要点：
- `get_inference_policy()` 返回 `actor_critic.act_inference`——只过 actor 网络取均值，**不带噪声、不经过 critic**，这正是部署时需要的确定性策略；
- 导出的 `policy_1.pt` 是 TorchScript 模块，可在无 Python 的 C++（libtorch）环境中加载；
- `logger` 记录的字段（92-103 行）就是评估 locomotion 策略的"标准体检表"：关节跟踪误差、速度跟踪误差、足底接触力。

### 1.3 `utils/helpers.py`（221 行）

| 函数 | 作用 | 精读点 |
|---|---|---|
| `class_to_dict(obj)` | 把嵌套配置类递归转成普通 dict | runner 侧只认 dict，此函数是两个世界的转换器 |
| `update_class_from_dict(obj, dict)` | 反向：dict 写回配置类 | 用于从外部覆盖配置 |
| `set_seed(seed)` | 同时固定 random/numpy/torch/torch.cuda 的种子 | `seed == -1` 时随机取一个，保证可复现性 |
| `parse_sim_params(args, cfg)` | 把命令行 + cfg.sim 合并成 `gymapi.SimParams` | `use_gpu_pipeline`、`physx.use_gpu` 在此确定 |
| `get_load_path(...)` | 按 `load_run`/`checkpoint` 找模型文件 | `-1` 表示"最新的 run / 最新的 checkpoint"，按文件名字典序取 max |
| `get_args()` | 定义全部命令行参数 | 见下表 |
| `export_policy_as_jit(...)` | 导出 TorchScript | 有 `memory_a` 属性（LSTM 策略）走 `PolicyExporterLSTM`，否则直接 script actor |
| `PolicyExporterLSTM` | LSTM 策略的导出包装 | 隐藏状态注册为 buffer，`@torch.jit.export reset_memory()` 暴露重置接口给 C++ |

`get_args()` 定义的自定义参数（叠加在 Isaac Gym 自带的 `--sim_device`、`--pipeline` 等之上）：

```
--task             任务名（默认 anymal_c_flat）
--resume           断点续训开关
--experiment_name / --run_name   实验名 / 运行名（决定日志目录）
--load_run / --checkpoint        加载哪个 run 的哪个模型（-1 = 最新）
--headless         无渲染模式
--rl_device        RL 算法所在设备（默认 cuda:0）
--num_envs / --seed / --max_iterations   覆盖配置的常用旋钮
```

参数优先级：**命令行 > 任务子配置 > 基类默认配置**。末尾的"名称对齐"把 Isaac Gym 的 `compute_device_id` 映射成 `sim_device_id`，并拼出 `cuda:0` 形式的 `sim_device`。

### 2.2 `utils/task_registry.py`（157 行）—— 装配工厂

`TaskRegistry` 类维护三个字典 `task_classes / env_cfgs / train_cfgs`，核心是两个工厂方法。

**`make_env(name, args, env_cfg)`（65-102 行）** 的装配流程：

```
get_cfgs(name)              → 取出注册的配置，并把 train_cfg.seed 拷给 env_cfg
update_cfg_from_args()      → 命令行覆盖（--num_envs、--seed）
set_seed(env_cfg.seed)      → 固定随机性
parse_sim_params(args, {"sim": class_to_dict(env_cfg.sim)})
                            → 配置类的 sim 段 + 命令行 → gymapi.SimParams
task_class(cfg, sim_params, physics_engine, sim_device, headless)
                            → 实例化环境（此时真正创建 4096 个机器人）
```

**`make_alg_runner(env, name, args, train_cfg, log_root)`（104-155 行）**：

```
确定 train_cfg（优先显式传入，否则按 name 查注册表）
update_cfg_from_args()      → 命令行覆盖
拼日志目录：logs/<experiment_name>/<月日_时分秒>_<run_name>/
class_to_dict(train_cfg)    → 配置类转 dict（runner 只认 dict）
OnPolicyRunner(env, train_cfg_dict, log_dir, device=args.rl_device)
若 resume：get_load_path() 找 checkpoint → runner.load()
```

精读要点：
- **环境侧用配置类（点号访问），算法侧用字典**——因为 rsl_rl 是独立库，不依赖 legged_gym 的配置体系，`class_to_dict` 是解耦边界；
- 日志目录命名含时间戳，保证每次训练互不覆盖；
- `resume` 时**先建目录再加载**，新 checkpoint 存到新目录，旧训练记录不受影响。

## 3. 配置体系

### 3.1 `envs/base/base_config.py`（55 行）—— 递归实例化

```python
class BaseConfig:
    def __init__(self):
        self.init_member_classes(self)

    @staticmethod
    def init_member_classes(obj):
        for key in dir(obj):                 # 遍历所有属性名
            if key == "__class__": continue
            var = getattr(obj, key)
            if inspect.isclass(var):         # 如果属性是"类"而不是值
                i_var = var()                # 实例化它
                setattr(obj, key, i_var)     # 用实例替换类
                BaseConfig.init_member_classes(i_var)   # 递归处理嵌套
```

精读要点：
- 配置写成"类嵌套类"（`class env: num_envs = 4096`），但**类属性无法被实例继承覆盖**——所以 `__init__` 把每个成员类实例化，之后 `cfg.env.num_envs` 就是普通实例属性，可以被命令行、子类、运行时代码随意改写；
- 子类覆盖配置的写法 `class env(LeggedRobotCfg.env): num_envs = 100`——**先继承父配置类，实例化时得到的就是合并后的结果**；
- 这是纯 Python 技巧，零依赖，比引入 omegaconf 等配置库轻量得多。

### 3.2 `envs/base/legged_robot_config.py`（244 行）—— 全部默认配置

两个顶层类：`LeggedRobotCfg`（环境）和 `LeggedRobotCfgPPO`（训练）。逐段精读：

| 配置段 | 关键字段 | 说明 |
|---|---|---|
| `env` | `num_envs=4096`、`num_observations=235`、`num_privileged_obs=None`、`num_actions=12`、`episode_length_s=20`、`send_timeouts=True` | 235 = 48 本体感知 + 187 高度；`send_timeouts` 开启 PPO 的超时价值补偿 |
| `terrain` | `mesh_type='trimesh'`、`curriculum=True`、`num_rows=10`、`num_cols=20`、`terrain_proportions=[0.1,0.1,0.35,0.25,0.2]`、`measure_heights=True`、`max_init_terrain_level=5`、`slope_treshold=0.75` | 网格课程地图；超过阈值的坡被修正为竖直面（防止"光滑陡坡上滑"的作弊解） |
| `commands` | `num_commands=4`、`resampling_time=10.`、`heading_command=True`、`ranges.lin_vel_x=[-1,1]` | 4 维指令 (vx, vy, wyaw, heading)；heading 模式下 wyaw 由朝向误差实时算出 |
| `init_state` | `pos`、`rot`、`lin_vel`、`ang_vel`、`default_joint_angles` | 出生状态；基类里关节角是占位符，子类必须覆盖 |
| `control` | `control_type='P'`、`stiffness/damping`（dict 按关节名通配）、`action_scale=0.5`、`decimation=4` | P=位置目标、V=速度目标、T=直接力矩 |
| `asset` | `file`、`foot_name`、`penalize_contacts_on`、`terminate_after_contacts_on`、`collapse_fixed_joints=True`、`replace_cylinder_with_capsule=True`、`self_collisions` | 胶囊替代圆柱：碰撞检测更快更稳；`self_collisions=1` 表示**禁用**自碰撞（位标志） |
| `domain_rand` | `randomize_friction=True [0.5,1.25]`、`randomize_base_mass=False ±1kg`、`push_robots=True interval 15s max 1m/s` | 域随机化三件套 |
| `rewards`（本体） | `only_positive_rewards=True`、`tracking_sigma=0.25`、`soft_dof_pos_limit=1.`、`max_contact_force=100.` | `soft_*_limit` 是 URDF 硬限位的打折系数（软约束） |
| `normalization.obs_scales` | `lin_vel=2.0`、`ang_vel=0.25`、`dof_pos=1.0`、`dof_vel=0.05`、`height=5.0` | 各观测分量缩放使数值同量级；另有 `clip_observations=100.`、`clip_actions=100.` |
| `noise.noise_scales` | `dof_pos=0.01`、`dof_vel=1.5`、`lin_vel=0.1`、`ang_vel=0.2`、`gravity=0.05`、`height=0.1` | 乘 `noise_level=1.0` 总开关；还要再乘 obs_scales（见 5.12 节） |
| `sim` | `dt=0.005`、`substeps=1`、`up_axis=1`、`physx.solver_type=1`、`num_position_iterations=4`、`max_gpu_contact_pairs=2**23` | TGS 求解器比 PGS 更稳；接触对上限决定能开多少环境 |

`LeggedRobotCfgPPO`：`seed` + `runner_class_name='OnPolicyRunner'` + 三个嵌套类 `policy`（网络结构与噪声）/ `algorithm`（PPO 超参）/ `runner`（训练控制与日志）。

> 注意 `policy_class_name='ActorCritic'` 等是**字符串**，`OnPolicyRunner` 里用 `eval()` 还原成类——配置因此可以跨包引用实现类，代价是牺牲类型安全。

### 3.3 `envs/a1/a1_config.py`（84 行）—— 继承覆盖范例

```python
class A1RoughCfg(LeggedRobotCfg):

    class control(LeggedRobotCfg.control):
        control_type = 'P'
        stiffness = {'joint': 20.}          # 键 'joint' 通配所有关节名
        damping = {'joint': 0.5}
        action_scale = 0.25                 # 动作幅度 ±0.25 rad 量级

    class asset(LeggedRobotCfg.asset):
```

### 5.6 `step`（79-103 行）—— 策略步主流程

```python
def step(self, actions):
    self.actions = torch.clip(actions, -100, 100).to(self.device)
    self.render()
    for _ in range(self.cfg.control.decimation):      # 4 次物理子步
        self.torques = self._compute_torques(self.actions).view(self.torques.shape)
        self.gym.set_dof_actuation_force_tensor(self.sim, unwrap(self.torques))
        self.gym.simulate(self.sim)
        if self.device == 'cpu': self.gym.fetch_results(self.sim, True)
        self.gym.refresh_dof_state_tensor(self.sim)   # PD 需要最新的 q、q̇
    self.post_physics_step()
    self.obs_buf = torch.clip(self.obs_buf, -100, 100)
    return self.obs_buf, self.privileged_obs_buf, self.rew_buf, self.reset_buf, self.extras
```

精读要点：
- **动作在 decimation 循环外算一次，力矩在循环内每步重算**——策略输出的是"目标位置"，PD 控制器在 200Hz 下持续根据最新关节状态调整力矩，这就是"50Hz 策略 + 200Hz 控制"的实现方式；
- 每个物理子步后只需 `refresh_dof_state_tensor`（PD 的反馈量），更贵的 root state / contact force 刷新留到 `post_physics_step` 做一次——按需刷新是 Isaac Gym 的性能守则；
- CPU 模式下 `fetch_results` 必须在 simulate 后显式调用；GPU 模式则异步。

### 5.7 `_compute_torques`（353-375 行）—— PD 控制器

```python

    torques = kp * (actions_scaled + default_dof_pos - dof_pos) - kd * dof_vel
elif control_type == 'V':   # 速度控制
    torques = kp * (actions_scaled - dof_vel) - kd * (dof_vel - last_dof_vel) / sim_dt
```

三种模式共用"action_scale 缩放 → 算力矩 → 限幅"的骨架。V 模式的 kd 项实际是加速度阻尼，T 模式完全无保护（实机慎用）。

### 5.15 奖励函数区（816-906 行）逐条精读

每个函数返回形状 `(num_envs,)` 的张量，由 `compute_reward` 加权求和。按用途四类：

**① 任务目标**

```python
_reward_tracking_lin_vel:  exp(−Σ(cmd_xy − v_xy)² / 0.25)     # 高斯型奖励，误差 0 时为 1
_reward_tracking_ang_vel:  exp(−(cmd_yaw − ω_yaw)² / 0.25)
_reward_feet_air_time:     Σ(腾空时长 − 0.5s) × 首次落地标志  # 见下
```

`feet_air_time` 的实现细节（882-893 行）值得细读：

```python
contact      = contact_forces[feet, 2] > 1.            # 本步接触
contact_filt = contact OR last_contacts                # 滤波：吞掉单步误报（PhysX 网格接触不可靠）
first_contact = (feet_air_time > 0) * contact_filt     # 腾空后首次落地
feet_air_time += dt
rew = Σ(feet_air_time − 0.5) × first_contact           # 只在落地瞬间结算
rew *= (‖cmd_xy‖ > 0.1)                                # 静止指令不给奖励
feet_air_time *= ~contact_filt                         # 落地后清零重新计时
```

**② 姿态与运动品质**：`lin_vel_z`（垂直速度平方）、`ang_vel_xy`（俯仰/侧倾角速度平方和）、`orientation`（投影重力 xy 分量平方和——机身水平时为 0）、`base_height`（与目标高度的平方误差，注意高度是相对 `measured_heights` 均值算的，地形自适应）。

**③ 能耗与平滑**：`torques`（Στ²）、`dof_vel`（Σq̇²）、`dof_acc`（Σ((q̇−q̇_prev)/dt)²）、`action_rate`（Σ(a−a_prev)²）。

**④ 安全约束**：

```python
_reward_collision:          Σ(‖penalized 部位接触力‖ > 0.1N)      # 计数惩罚
_reward_dof_pos_limits:     Σ(超出软限位的距离)                     # 连续惩罚
_reward_dof_vel_limits:     Σ(|q̇| − 软速度限位).clip(0, 1)         # clip 防爆

_reward_stumble:            any(‖足部水平力‖ > 5×|竖直力|)           # 踢到竖直面
_reward_stand_still:        Σ|q − q_default| × (‖cmd_xy‖ < 0.1)   # 静止时不许乱动
_reward_feet_contact_forces: Σ(‖足部力‖ − 100N).clip(min=0)        # 落地冲击
_reward_termination:        reset_buf × ~time_out_buf              # 只罚真终止
```

### 7.3 `modules/actor_critic.py`（155 行）—— 高斯策略网络

```python
class ActorCritic(nn.Module):
    is_recurrent = False
    def __init__(...):
        # Actor：Linear(obs,512)→ELU→Linear(512,256)→ELU→Linear(256,128)→ELU→Linear(128,12)
        # Critic：同上但输出 1 维
        self.std = nn.Parameter(1.0 × ones(num_actions))    # ★ 可学习、与状态无关
        Normal.set_default_validate_args = False            # 关参数检查提速

    def update_distribution(self, obs):
        mean = self.actor(obs)
        self.distribution = Normal(mean, mean*0. + self.std)

    def act(obs):            update_distribution; return distribution.sample()   # 训练用
    def act_inference(obs):  return self.actor(obs)                              # 部署用（纯均值）
    def evaluate(critic_obs): return self.critic(critic_obs)
    def get_actions_log_prob(a): return distribution.log_prob(a).sum(-1)         # 12 维联合对数概率
    @property entropy:       return distribution.entropy().sum(-1)
```

精读要点：
- σ 是 `nn.Parameter` 而非常数——它跟着策略损失一起被梯度下降调节，训练日志里的 `Mean action noise std` 就是它的均值，**收敛过程通常能看到它从 1.0 缓慢下降**；
- `Normal(mean, mean*0. + self.std)` 的写法是把 `(12,)` 的 σ 广播到 batch 维；
- `reset(dones)` 在 MLP 版是空操作，RNN 版才有实际意义——接口统一，runner 无需区分。

### 7.4 `storage/rollout_storage.py`（234 行）—— 经验池与 GAE

**数据结构**：预分配连续显存，形状 `[24, num_envs, *]`（时间维在前）：

```python
observations / privileged_observations / rewards / actions / dones
actions_log_prob / values / returns / advantages / mu / sigma      # PPO 专用
saved_hidden_states_a / saved_hidden_states_c                      # RNN 专用
```

`Transition` 内嵌类是"一步数据"的临时容器：`act()` 填一半（obs/action/V/log_prob），`process_env_step` 填另一半（r/done），然后 `add_transitions` 整体拷入第 `step` 槽位。

**`compute_returns(last_values, γ, λ)`（123-137 行）—— GAE 反向递推**：

```python
advantage = 0
for step in reversed(range(24)):
    next_values = last_values if step == 23 else values[step+1]   # 末端用自举值
    next_is_not_terminal = 1 − dones[step]                        # done 则切断传播
    δ = r[step] + γ·next_values·(1−done) − V[step]
    advantage = δ + γ·λ·(1−done)·advantage
    returns[step] = advantage + V[step]
advantages = returns − values
advantages = (adv − mean) / (std + 1e-8)                          # 全 buffer 归一化
```

注意递推方向：**从最后一步往第一步算**，`advantage` 变量携带未来的折扣信息。

**两个 mini-batch 生成器**：
- `mini_batch_generator`（147-183 行，MLP 用）：把 `[24, N, *]` 展平成 `24N` 条独立样本，`randperm` 打乱后切成 4 批，跑 5 个 epoch（同一份排列重复用）；
- `reccurent_mini_batch_generator`（186-233 行，RNN 用）：先用 `split_and_pad_trajectories` 按 done 切轨迹并 padding 成批，按环境维分 mini-batch（保时序），同时取出**每段轨迹起点处的 RNN 隐藏状态**——RNN 训练必须从轨迹起点的前向状态开始重放。

### 7.5 `algorithms/ppo.py`（187 行）—— PPO 更新

**`act(obs, critic_obs)`（90-102 行）**：采样动作、评估 V、算 log_prob、记录 μ/σ——全部 `.detach()`，rollout 阶段不建图。

**`process_env_step(rewards, dones, infos)`（104-114 行）**：

```python
if 'time_outs' in infos:                                   # ★ 超时价值补偿
    rewards += γ × values × time_outs
storage.add_transitions(transition)
actor_critic.reset(dones)                                  # RNN 隐藏状态清零（MLP 空操作）
```

**`update()`（120-187 行）** 逐段：

```python
for obs_b, critic_obs_b, a_b, old_V_b, adv_b, ret_b, old_logp_b, old_μ_b, old_σ_b, hid, masks \
    in storage.mini_batch_generator(4, 5):                  # 4 批 × 5 epoch

    actor_critic.act(obs_b)                                # 重建当前策略的分布
    logp_b = get_actions_log_prob(a_b)
    V_b = evaluate(critic_obs_b)

    # ① KL 自适应学习率（高维高斯间 KL 的解析式）
    kl = Σ[ log(σ/σ_old) + (σ_old² + (μ_old−μ)²)/(2σ²) − 0.5 ]
    if kl > 0.02: lr /= 1.5（下限 1e-5）; if kl < 0.005: lr ×= 1.5（上限 1e-2）

    # ② 截断策略损失
    ratio = exp(logp_b − old_logp_b)
    surrogate_loss = max(−adv·ratio, −adv·clip(ratio, 0.8, 1.2)).mean()

    # ③ 截断价值损失
    V_clipped = old_V_b + (V_b − old_V_b).clamp(±0.2)
    value_loss = max((V_b−ret)², (V_clipped−ret)²).mean()

    # ④ 总损失 + 梯度步
    loss = surrogate_loss + 1.0×value_loss − 0.01×entropy
    zero_grad → backward → clip_grad_norm(1.0) → step

storage.clear()                                            # on-policy：数据用完即弃
```

注意 KL 计算包在 `torch.inference_mode()` 里——它只用于调学习率，不需要梯度。

### 7.6 `modules/actor_critic_recurrent.py`（115 行）—— RNN 策略

继承 `ActorCritic`，在 MLP 前加 `Memory` 模块（LSTM/GRU）：

```python
obs → memory_a (RNN) → actor (MLP) → 动作均值      # actor 的"输入维度"变成了 rnn_hidden_size
obs → memory_c (RNN) → critic (MLP) → 价值
```

`Memory.forward` 的双模式（100-111 行）很巧妙：

- **推理模式**（masks=None，rollout 时）：输入 unsqueeze 加时间维，单步前向，隐藏状态存 `self.hidden_states`；
- **批训练模式**（masks 非 None，update 时）：输入是整段 padded 轨迹 + 起点隐藏状态，前向后用 `unpad_trajectories` 去掉 padding 还原成样本流。

`reset(dones)` 把 done 环境的隐藏状态切片清零——每个环境的 RNN 记忆独立生命周期。

### 7.7 `utils/utils.py`（70 行）—— 轨迹切分

`split_and_pad_trajectories(tensor, dones)`：把 `[time, envs, *]` 的 buffer 在 done 处切开，padding 到最长轨迹，返回 `(padded, masks)`。文件 docstring 里有清晰的图解示例。`unpad_trajectories` 是其逆操作。这对函数是 RNN-PPO 的基础设施，MLP 路径用不到。

## 8. 端到端：一次迭代的完整调用序列

把前面所有章节串起来——训练循环中**一次迭代**（1.6 秒左右）发生的全部事情：

```
OnPolicyRunner.learn 第 it 次迭代
│
├─ 【Rollout 阶段】重复 24 步（inference_mode，无梯度）
│   │
│   ├─ PPO.act(obs, critic_obs)
│   │     ├─ ActorCritic.act: obs(4096,235) → actor MLP → μ(4096,12)
│   │     │                    → Normal(μ, σ).sample() → actions
│   │     └─ ActorCritic.evaluate: critic MLP → V(4096,1)
│   │        记录到 transition：obs / actions / values / log_prob / μ / σ
│   │
│   ├─ LeggedRobot.step(actions)                          [legged_robot.py:79]
│   │     ├─ clip(actions, ±100)
│   │     ├─ ×4 物理子步: _compute_torques(PD) → set_dof_actuation_force → simulate
│   │     │              → refresh_dof_state_tensor
│   │     └─ post_physics_step()                          [:105]
│   │           ├─ refresh root_state / contact_force
│   │           ├─ _post_physics_step_callback            [:320]
│   │           │     ├─ 每 500 步重采样指令 / heading→yaw 速率换算
│   │           │     ├─ _get_heights() 测地形高度
│   │           │     └─ 每 750 步 _push_robots() 随机推搡
│   │           ├─ check_termination()                    [:138]  基座触地 | 超时
│   │           ├─ compute_reward()                       [:190]  17 项奖励加权和 × dt
│   │           ├─ reset_idx(done 环境)                   [:145]  课程升降级 + 状态重置
│   │           └─ compute_observations()                 [:209]  拼 235 维观测 + 加噪
│   │
│   └─ PPO.process_env_step(r, done, infos)               [ppo.py:104]
│         ├─ 若 time_out: r += γ·V                        超时价值补偿
│         └─ storage.add_transitions()                    拷入 [step, :, *] 槽位
│
├─ 【GAE 阶段】PPO.compute_returns(critic_obs)             [ppo.py:116]

│
└─ 【收尾】log()（TensorBoard + 终端打印）→ 每 50 次 save(model_{it}.pt)

数据规模：每次迭代 4096 环境 × 24 步 = 98,304 条转移；1500 次迭代 ≈ 1.47 亿步经验。
```
