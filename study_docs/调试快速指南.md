# RL 训练调试快速指南

## 1. 打开专用 VS Code 窗口

在终端执行：

```bash
/home/lixiang/.vscode-rl-debug/open-rl.sh
```

使用标题带有 **[RL Python 3.8 调试专用]** 的窗口。该实例使用独立的用户数据和扩展目录，安装了兼容 Python 3.8 的 Python Debugger `2024.2.0`，不影响普通 VS Code 的新版调试器。

首次使用或更换扩展后，按 **Ctrl + Shift + P**，执行 **Developer: Reload Window**。若提示工作区信任，确认是自己的项目后选择信任。

**如果仍提示调试器最低要求 Python 3.9：** 先保存文件并停止调试，完全关闭标题带有 `[RL Python 3.8 调试专用]` 的窗口，再执行上面的启动脚本。安装扩展时已打开的窗口可能仍缓存新版调试器；仅再次运行脚本不一定会重启原有扩展宿主。重新打开后，在扩展面板搜索 `@id:ms-python.debugpy`，确认版本为 `2024.2.0`。不要点击“更改 Python 解释器”来升级项目 Python。

## 2. 启动训练调试

1. 打开训练入口：`/home/lixiang/AI Study/RL/legged_gym_study/legged_gym/scripts/train.py`。
2. 在第 60 行（创建环境）左侧点击设置断点，或按 **F9**。
3. 按 **Ctrl + Shift + D**，选择 **PPO 训练单步调试（4 环境 / 2 轮）**。
4. 按 **F5** 启动。配置已关闭入口暂停，程序会运行到第 60 行断点；前面的导入与初始化仍需执行。

先用 **F5** 到达断点，再用 **F10 / F11** 单步。每次停止后重新启动都会从头执行，这是正常行为；F10 不会直接跳到断点。若修改了启动配置，须停止当前调试后重新启动才生效。若未到断点就退出，请查看终端的报错；若断点显示为空心或灰色，请检查“断点”面板是否启用了断点，以及当前使用的启动配置是否正确。

配置已指定 `legged_gym` Conda 环境的解释器，不需要手动执行 `conda activate`。默认任务为 `anymal_c_flat`，使用 4 个环境、2 轮训练和无界面模式。

配置还将 `/home/lixiang/anaconda3/envs/legged_gym/bin` 加入调试进程的 PATH，使 `gymtorch` 能找到已安装的 Ninja。仅指定 Python 解释器并不等于完整激活 Conda 环境；遇到 `Ninja is required to load C++ extensions` 时，应先检查调试配置的 `env.PATH`。

调试配置的 `LD_LIBRARY_PATH` 优先使用当前 PyTorch 自带的库与 Conda 库，避免系统 CUDA 11.1 的旧 cuBLAS 库抢先加载。这些设置仅作用于当前调试进程，不修改其他项目或系统环境。

## 3. 单步操作

| 快捷键 | 功能 |
| --- | --- |
| F9 | 添加或取消断点 |
| F10 | 执行下一行，不进入函数 |
| F11 | 进入函数 |
| Shift + F11 | 跳出当前函数 |
| F5 | 继续运行到下一断点 |
| Shift + F5 | 停止调试 |

暂停时，可在左侧“变量”面板查看数据，也可在“调试控制台”输入表达式，例如 `args`。停在采样循环时，可查看 `obs.shape`、`actions[0]`、`rewards` 等；变量须在对应代码执行后才存在。
